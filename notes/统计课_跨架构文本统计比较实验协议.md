# 跨架构机器翻译文本统计比较实验协议

## Statistics Group Project — Experimental Protocol (Final)

---

## 一、研究概述

### 核心问题

传统统计机器翻译架构（SMT, phrase-based）与 Transformer 大语言模型架构（decoder-only LLM）生成的中英译文，在**词汇丰富度、句子复杂度分布、情感倾向、风格计量学**四个维度上是否存在统计显著的差异？

### 研究意义

- 从**统计语言学**角度量化两种机器翻译范式的输出差异
- 为文本生成系统的选择提供基于证据的指导
- 验证不同架构在语言统计特征上的可区分性

## 二、实验设计

### 2.1 因子结构

| 因子 | 水平数 | 具体水平 |
|:----|:------:|:--------|
| **架构 (A)** | 2 | Moses SMT vs LLM（聚合 6 个模型） |
| **语言方向 (B)** | 2 | 中文→英文, 英文→中文 |
| **体裁 (C)** | 2 | 新闻, 文学 |

**设计类型**：2 × 2 × 2 完全析因设计（主要分析）

**LLM 子因子（次要分析）**：每个源文本由 6 个 LLM 模型分别翻译，构成重复测量：
- deepseek-v4-pro, deepseek-v4-flash, glm-5.1, glm-5, kimi-k2.6, qwen3.6-plus
- 次要分析：6 个 LLM 模型之间的差异比较

**样本量**：
- 每 cell 10 篇源文本（基于功效分析：α = 0.05, power = 0.80, 预期 d ≈ 0.8）
- 8 cell × 10 = **80 篇源文本**
- 每篇由 SMT + 6 个 LLM 翻译 → **7 个译文版本**
- 总分析单元：80 × 7 = **560 篇翻译输出文本**

### 2.2 源文本构成

| 体裁 | 中文原创 | 英文原创 | 来源 |
|:----:|:--------:|:--------:|:----|
| **新闻** | 20 篇 | 20 篇 | NYT / 新华社公开文章（2023年后，确保不在LLM训练数据中） |
| **文学** | 20 篇 | 20 篇 | 从 ≥5 位风格迥异的中国作家（余华、莫言、苏童、王小波、张爱玲等）作品中提取的段落 / 英文文学短篇 |
| **合计** | 40 篇 | 40 篇 | **80 篇源文本** |

**长度控制**：每篇 200-800 英文词（或等量中文），以确保句子数量足以支持句长分布分析和情感分段。

### 2.3 源文本获取策略

| 语言 | 文学 | 新闻 |
|:----|:----|:----|
| **中文** | `~/BOOKS/汉语文学/` 中 ≥5 位作者（见工具 `extract_source_texts.py`） | 新华社公开报道（第1周爬取） |
| **英文** | Project Gutenberg 短篇 / 用户已有的英文写作 | NYT Archive API（第1周） |

## 三、两种翻译系统的实现

### 3.1 传统 ML 组：Moses SMT

**技术架构**：短语级别统计机器翻译（Phrase-based SMT）

| 组件 | 工具 | 说明 |
|:----|:----|:----|
| 解码器 | **Moses** (GitHub: moses-smt/mosesdecoder) | 纯 C++ SMT 解码器，非神经 |
| 词对齐 | **GIZA++** | IBM Model 4 |
| 短语抽取 | Moses 内置 | 基于词对齐的短语表提取 |
| 语言模型 | **KenLM** | 5-gram，modified Kneser-Ney 平滑 |
| 调优 | **MERT** (Minimum Error Rate Training) | 以 BLEU 为目标 |
| 部署方式 | **Docker** (`amake/moses-smt`) | 预装全部依赖 |

**训练数据**：
- WMT news-commentary v16-v18（中英平行语料，~300K 句）
- 目标语言单语数据用于训练 KenLM（News Crawl）

**操作流程**：

```bash
# Step 1: 拉取 Docker 镜像
docker pull amake/moses-smt

# Step 2: 准备语料（tokenize + truecase + clean）
# Step 3: 词对齐
# Step 4: 短语抽取 + 评分
# Step 5: 训练语言模型 (KenLM)
# Step 6: MERT 调优
# Step 7: 批量翻译
echo "待翻译句子" | docker run -i --rm -v $(pwd)/model:/model amake/moses-smt moses -f /model/moses.ini
```

**预期训练时间**：2-4 小时 / 方向（CPU，~100K 平行句）

**预期 BLEU**：ZH→EN 约 20-25, EN→ZH 约 20-25

### 3.2 Transformer 组：LLM（多模型）

**模型**：OpenCode Go 支持的 6 个主流模型，全部禁用推理模式（快速翻译）

| # | 模型名（API 使用） | 上下文 | 推理模式 |
|:-:|:------------------|:-----:|:-------:|
| 1 | `deepseek-v4-pro` | 1M | ❌ 禁用 |
| 2 | `deepseek-v4-flash` | 1M | ❌ 禁用 |
| 3 | `glm-5.1` | 203K | ❌ 禁用 |
| 4 | `glm-5` | 128K | ❌ 禁用 |
| 5 | `kimi-k2.6` | 256K | N/A |
| 6 | `qwen3.6-plus` | 260K | N/A |

> ⚠ API 注意：OpenCode Go 端点使用短名（如 `deepseek-v4-flash`），不需要加 `opencode-go/` 前缀。

**统一参数**（全实验、全模型一致）：

| 参数 | 值 | 说明 |
|:----|:---|:-----|
| 温度 | 0.0 | 尽量降低随机性（见下方确定性验证） |
| seed | 42 | API 尽力支持，但不保证确定性 |
| 提示词 | **统一模板** | 见附录 A |
| 推理模式 | 禁用 | 仅输出翻译，无 chain-of-thought |

**质量门控**（自动检查每条翻译输出）：
1. `finish_reason` 非 `"length"`（未截断）
2. 语言检测：输出语言与目标语言一致（Unicode 范围启发式）
3. 长度比：输出/源文在 0.2~3.0 范围内
4. 拒绝检测：不包含 "I cannot translate"、"抱歉" 等拒绝短语

**执行方式**：使用 `llm_batch_translate.py`（批量翻译脚本）
- 并行 workers（默认 4）
- 按模型分目录输出（`translations/{model_slug}/`）
- 每文件附带 JSON 元数据（model_served, token_usage, timestamp 等）
- 原子写入 checkpoint，断点续传

## 四、特征提取流水线

所有 160 篇译文经过同一套流水线处理，输出统一的特征矩阵。

### 4.1 词汇丰富度 Lexical Diversity

| 指标 | 缩写 | 说明 | 工具 |
|:----|:----|:----|:----|
| 标准化类符/形符比 | STTR | 1000 词窗口的 TTR 均值 | `lexical-diversity` (pip) |
| 文本词汇多样性度量 | MTLD | 基于 TTR 阈值的分段因子均值 | `lexical-diversity` |
| 超几何分布 D | HD-D | 基于词汇出现概率的采样不变量 | `lexical-diversity` |

**注意**：中文先做 jieba / spaCy 分词后计算。STTR 作为主要指标，MTLD/HD-D 作为辅助。

### 4.2 句子复杂度 Sentence Complexity

| 指标 | 说明 | 方法 |
|:----|:----|:----|
| 句长分布 | 每篇文本的句子长度（以词/token为单位） | spaCy 分句 + count |
| 分布统计量 | 均值、标准差、偏度、峰度 | `scipy.stats` |
| 分布比较 | 两样本 KS 检验（SMT vs LLM） | `scipy.stats.ks_2samp` |
| 依存深度（可选） | 句法树最大深度 | spaCy dependency parse |

### 4.3 情感倾向 Sentiment

**模型**：XLM-RoBERTa 多语言情感分类器
- `cardiffnlp/twitter-xlm-roberta-base-sentiment`
- 支持中文 + 英文
- 输出三元概率：positive / neutral / negative

**每篇文本输出**：
- 三个类别的平均概率
- 极性得分 = P(pos) - P(neg)
- 情感波动 = 分句概率向量的方差

```python
from transformers import pipeline

sentiment_pipeline = pipeline(
    "sentiment-analysis",
    model="cardiffnlp/twitter-xlm-roberta-base-sentiment"
)

result = sentiment_pipeline(text)
# 返回 [{'label': 'positive', 'score': 0.95}, ...]
```

### 4.4 风格计量学 Stylometry

| 指标 | 说明 | 工具 |
|:----|:----|:----|
| POS 标签分布 | Universal POS 各类比例 | spaCy POS tagger |
| Shannon 熵 | POS 分布的多样性度量 H = -Σ p(i)·log₂ p(i) | `scipy.stats.entropy` |
| 功能词频率 | 各语言常用功能词比例 | 自定义列表 + 计数 |
| 余弦相似度 | 两两文本 POS 分布之间的余弦距离 | `sklearn.metrics.pairwise` |

**功能词列表**（各语言独立）：

| 语言 | 来源 | 数量 |
|:----|:----|:----|
| 英文 | 功能词列表（the, a, of, in, to, ...） | ~150 |
| 中文 | 虚词列表（的、了、在、是、有、...） | ~100 |

### 4.5 输出 CSV 格式

```
filename, architecture, model, direction, genre, source_lang, target_lang,
source_text_length,
sttr, mtld, hdd,
sent_mean_len, sent_std_len, sent_skew,
sent_pos_score, sent_neg_score, sent_neu_score, sent_volatility,
pos_entropy, func_word_ratio,
bleu_score
```

**列说明**：
- `architecture`: `"smt"` 或 `"llm"`（主分析分组）
- `model`: 具体模型名，如 `deepseek-v4-flash`（SMT 行记为 `moses`；次要分析分组用）
- `source_text_length`: 源文本词数（ANCOVA 协变量）

## 五、统计分析计划

### 5.1 四项核心假设

| 编号 | 假设 | 零假设 H₀ | 检验方法 |
|:----:|:----|:---------|:--------|
| **H1** | 两种架构译文的 STTR 均值不同 | μ_SMT = μ_LLM | 混合效应模型 `lmer(STTR ~ architecture*genre + source_length + (1\|source_text_id)` |
| **H2** | 两种架构译文的句长分布不同 | 分布相同 | 两样本 KS 检验 + 混合效应模型检验均值句长 |
| **H3** | 两种架构译文的情感极性得分不同 | μ_SMT = μ_LLM | 混合效应模型（同上结构） |
| **H4** | 两种架构译文的 POS Shannon 熵不同 | μ_SMT = μ_LLM | 混合效应模型（同上结构） |

### 5.2 分析方法

**Step 1: 聚合策略**（针对 LLM 多模型）
- **主分析**：每篇源文本下 6 个 LLM 特征值取**中位数**（稳健聚合），与 SMT 进行 2×2×2 比较
- **次要分析**：仅 LLM 数据，model 作为 6 水平的固定效应，不聚合

**Step 2: 描述统计**
- 每 cell 的均值、标准差、95% CI（bootstrapped, 10,000 次）
- 可视化：分面箱线图（architecture × direction × genre）

**Step 3: 主分析假设检验**（混合效应模型）
- `lmer(metric ~ architecture * genre + source_length + (1 | source_text_id))`
- 逐语言方向分层
- 源文本 ID 作为随机截距（控制重复测量非独立性）
- 源文本长度作为协变量（控制长度对 STTR 等的影响）

**Step 4: 效应量**
- 混合效应模型：边际 R² / 条件 R²（Nakagawa's R²）
- Cohen's d（基于模型估计边际均值）
- 所有结果报告 95% 置信区间

**Step 5: 次要分析**（LLM 模型间比较）
- `lmer(metric ~ model * genre + source_length + (1 | source_text_id))`
- 事后比较：Tukey HSD 校正

**Step 6: 分类验证**
- SVM (linear kernel) 二分类：SMT vs LLM
- 特征：全部 4 维度指标
- 验证：GroupKFold（按源文本分组，防止数据泄露）
- 指标：Accuracy, F1, MCC (Matthews Correlation Coefficient)

**Step 7: 多重比较校正**
- 四项假设各使用独立的 Holm-Bonferroni 校正（非跨假设校正）

### 5.3 功效分析

依据 Oracle 审核计算结果：

| 参数 | 值 |
|:----|:----|
| 预期效应量 (Cohen's d) | 0.8（基于文献保守估计） |
| 显著性水平 α | 0.05（Holm 校正后） |
| 统计功效 | 0.80 |
| 所需每 cell 样本量 | ~10 篇 |
| 实际每 cell 样本量 | 10 篇 ✅ |

### 5.4 敏感性分析

- **度量稳健性**：STTR / MTLD / HD-D 三种词汇多样性指标是否给出同一方向结论
- **离群值影响**：排除 ±3 SD 极值后的结果是否一致
- **文本长度影响**：将文本按长度分层，检验效应是否随长度变化

## 六、预期结果与解释框架

### 6.1 预期结果模式

| 维度 | 预测方向 | 合理解释 |
|:----|:--------|:--------|
| 词汇丰富度 | LLM > SMT | LLM 训练数据多样，生成时词汇选择更丰富；SMT 受限于短语表覆盖范围 |
| 句长分布 | SMT 更均匀，LLM 更接近人类分布 | SMT 解码器有长度惩罚 + n-gram LM 约束；LLM 无显式长度控制 |
| 情感倾向 | 差异较小 | 两种架构在翻译时都倾向于中性化，但 LLM 可能保留更多源文情感色彩 |
| 风格计量学 | LLM 的 POS 熵更高 | LLM 可生成更多样的句法结构，SMT 倾向于固定短语模板 |

### 6.2 交互效应预期

- **架构 × 体裁**：文学体裁中架构差异预计大于新闻体裁（文学语言更自由，SMT 的短语限制更明显）
- **架构 × 方向**：中→英方向差异预计大于英→中（中文分词对 SMT 的挑战更大）

### 6.3 如果结果不显著

- 检查中文分词质量是否影响了词汇多样性指标
- 检查 Moses 模型是否训练充足（BLEU 是否在合理范围）
- 考虑文本长度是否足以暴露出架构差异

## 附录 A：提示词模板（全实验统一）

```
System: You are a professional translator. You translate texts accurately and naturally,
preserving the original meaning, tone, and style.

User: Translate the following [新闻/文学] text from [中文/英文] to [英文/中文].
Output only the translation. Preserve paragraph breaks.

[源文本全文]
```

温度 (temperature) = 0.0。

> ⚠ **确定性验证**（2026-06-07）：在 OpenCode Go API 上，`temperature=0.0` + `seed=42` **不保证确定性输出**。
> 对所有 6 个模型 × 5 篇样本 × 3 次运行的验证显示：
> - ZH→EN：中等差异（self-BLEU ~60-85）
> - EN→ZH：高度差异（self-BLEU ~0，每次措辞完全不同）
> 这意味着 LLM 输出具有固有随机性。本实验测量的是两种架构翻译输出的**统计分布特征**，
> LLM 的固有方差本身是一个可分析维度，不属于需要"消除"的问题。
